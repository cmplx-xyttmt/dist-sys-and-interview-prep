Nine rungs, one mission each, then the explainer again

Start here

On Thursday Sep 17, 2026 you read sprites-explainer.html, a page about how Fly.io built Sprites, and reported: "didn't understand most of it, huge knowledge gaps". That was the page's fault, not yours. It was written as a summary for someone who already had the vocabulary. Go to its section 04 and count what it assumes: block device, filesystem, NVMe, read-through cache, dm-cache, immutability, content addressing, object storage, S3, SQLite, write-ahead log, log shipping, metadata versus data, JuiceFS, GFS. Fifteen ideas in six paragraphs, each mentioned once and never built up.

None of them is hard on its own. They stack, and the explainer starts at the top. So this guide is the stack: nine rungs, in the order each one needs the one before. Every rung ends with a mission (a measurement in L0, a small program in L1 to L7, a paragraph in L8) and a check it has to pass. When the check passes, you tick the rung, and the sidebar fills. This is the same shape as the heuristic contests guide, with missions instead of scored solvers.

How to use it Rungs are never locked; read ahead whenever you like. A rung counts as passed when its mission's check passed, not when the reading is done. Every reading and every mission step has a checkbox that remembers itself (this browser only; use Export in the sidebar before clearing browser data, and paste the file into dist-sys-interview-prep/sprites-guide/progress-export.json so a Claude session can read it).

"Bet 1, bet 2, bet 3"
The three items in the explainer's section 03, The three design bets: (1) kill the container image, (2) object storage is the source of truth, (3) inside-out orchestration. Spelled out on the map page.
Sprites
Fly.io's product, launched January 2026: a Linux virtual machine that creates in one to two seconds, keeps its disk, sleeps when idle and costs almost nothing asleep. Docs at fly.io/sprites.
Fly Machines
Fly.io's older product: a container-based virtual machine that takes about a minute to create and whose disk lives on one physical server. The explainer's section 06 compares the two.
DDIA
Designing Data-Intensive Applications by Martin Kleppmann, the textbook your dist-sys roadmap is built around. Chapter 3 is storage engines, chapter 5 is replication, chapter 6 is partitioning.
Gossip Glomers, Maelstrom
Gossip Glomers is Fly.io's set of distributed-systems programming challenges (echo, unique ids, broadcast, counters, logs, transactions). Maelstrom is the test harness they run on: it starts your program as several nodes, sends them messages, injects partitions and checks the results. Both were already on your roadmap; here they are rung L6's mission.
Corrosion
Fly.io's open-source service that gossips fleet state (which Sprite lives on which host) between all their servers, using SQLite plus conflict-free replicated data types. github.com/superfly/corrosion. Rung L6.
Litestream
A tool by Ben Johnson (now at Fly.io) that continuously copies a SQLite database's write-ahead log to object storage, so the database can be restored from there. litestream.io. Rungs L1 and L4.

In this guide a mission is 1 to 2 hours; the 20-to-40-minute size in the missions document is for the checkpoints a generated course would attach to a reading. Publishing: the series on your site

The full plan, the introduction draft, the title options and what a public version of the ladder would change are on the publishing page. Each rung page ends with a "Write about it" section naming its post. The short version:

Your site is the Hugo repository (Hugo is the static-site generator that turns Markdown into the pages) at ~/Projects/cmplx-xyttmt.github.io (cmplx-xyttmt.github.io). Section 8 of the dist-sys roadmap already says what goes there: interactive explorations rather than prose posts, with a fixed limit on polishing time (60 minutes a post) so writing never displaces the prep itself.

  • Series title: "What I had to learn to understand Sprites". One post per rung, L0 to L7. Each post is the rung's mission: the code (small enough to read whole), the check, the surprise, and where the idea sits in the Sprites design. Where a rung has a natural interactive (L2's manifest, L3's cache hit ratio, L6's gossip rounds) the post gets one; otherwise code and a figure.
  • Cadence: the post is written the same week as the rung, 60 minutes at most. If it doesn't fit, it waits for the next rung and ships as a pair.
  • Closing post: the explainer itself, republished once you can annotate it, with this ladder as its "start here".
  • The showcase project gets its own five posts, one per phase, listed in its document.
